## 🚀 Введение

**Sprint Planner** — это инструмент для объективного и прозрачного планирования спринтов в продуктовой разработке. Приложение помогает Product Owner формировать бэклог спринта на основе формализованных критериев ценности, объективных оценок трудозатрат и жёстких ограничений по ресурсам команды.

В основе системы лежит методика, описывающая единый подход к приоритизации и отбору задач. Приложение реализует эту методику, предлагая три различных алгоритма отбора и гибкие настройки.

| **Scrum Master** | Понимание логики взаимодействия методов отбора с моделью ёмкости команды. Возможность диагностировать причины перегрузки или недозагрузки ролей. |
| **Команда разработки** | Прямая зависимость между оценкой трудозатрат, ценностью задачи и её попаданием в спринт. Прозрачные правила, исключающие «ручное продавливание» задач. Участие в уточнении оценок. |
| **Руководители и стейкхолдеры** | Ясное обоснование состава спринта, основанное на формализованных критериях и объективных ограничениях. |

## 💎 Ценность приложения

- **Объективность** – все задачи оцениваются по единым критериям с заданными весами.
- **Прозрачность** – каждый шаг отбора можно объяснить и воспроизвести.
- **Гибкость** – возможность настраивать критерии под текущие OKR и выбирать подходящий алгоритм отбора.
- **Эффективность** – максимизация ценности спринта при ограниченных ресурсах.
- **Контроль загрузки** – детальный мониторинг загрузки каждой роли с визуальными индикаторами перегрузки.
- **Автоматизация** – рутинные расчёты выполняются мгновенно, освобождая время для анализа.

## 🧠 Основные понятия и алгоритмы

### 🔹 Критерии оценки и Priority Score

Каждая задача оценивается по нескольким критериям (например, вклад в OKR, влияние на UX, стратегическая важность, риск бездействия). Для каждого критерия задаётся **вес** (в процентах, сумма весов = 100%) и **шкала оценки** от 1 до 10. На основе баллов и весов рассчитывается **Priority Score** (интегральный приоритет) по формуле:

<div class="formula">
Priority Score = Σ (оценка_критерия × вес_критерия) / 100
</div>

Значение Priority Score находится в диапазоне от 1 до 10 и отражает, насколько задача соответствует утверждённой стратегии.

### 🔹 Трудозатраты (Effort)

Трудозатраты оцениваются в человеко-часах **по пяти ролям**:
- UI/UX
- CA (аналитик)
- FE (frontend)
- BE (backend)
- QA (тестирование)

Суммарный Effort задачи — это сумма часов по всем ролям.

### 🔹 Ёмкость команды (Capacity)

Для каждой роли рассчитывается доступное время в спринте:

<div class="formula">
Capacity = (Длительность_спринта_дни – Отпуск_дни) × 8 часов × (FTE% / 100) × Коэффициент_доступности / 100 – 7 часов (встречи) – 9% (саморазвитие)
</div>

- **Коэффициент доступности** по умолчанию 93,5% — учитывает переключения, болезни, неплановые работы.
- **Порог алерта** (в процентах) определяет, при каком превышении ёмкости появляется красная подсветка. Не влияет на алгоритмы отбора — они всегда работают со строгими ограничениями.

### 🔹 Плотность ценности (Value Density)

Отношение Priority Score к Effort:

<div class="formula">
Value Density = Priority Score / Effort
</div>

Показывает, сколько единиц приоритета приносит один час трудозатрат. Используется в алгоритмах Value Density и Hybrid.

### 🔹 Алгоритмы отбора

Все три алгоритма используют общую базу (`selectTasksUniform`) — жадный алгоритм (greedy knapsack) с проверкой ёмкости по ролям. Задачи с нулевым Effort и вручную исключённые автоматически пропускаются.

#### Priority-Effort Matrix

Задачи распределяются по 4 квадрантам относительно медиан Priority Score и Effort:

<div class="formula">
           Высокий приоритет
                │
    Q2          │          Q1
    Стратегич.  │     Лёгкие победы
    (↑effort)   │     (↓effort, ↑priority)
 ───────────────┼───────────────── Медиана effort
    Q4          │          Q3
    Откладывать │     Заполнители
    (↓priority) │     (↓priority, ↓effort)
                │
           Низкий приоритет
</div>

**Порядок отбора**: Q1 → Q2 → Q3 → Q4.

| Квадрант | Сортировка внутри | Стратегия |
|----------|------------------|-----------|
| Q1 | `priorityScore` ↓ | Самые ценные и лёгкие — первыми |
| Q2 | `effort` ↑, затем `priorityScore` ↓ | Среди важных берём менее тяжёлые |
| Q3 | `priorityScore` ↓ | Заполняют оставшуюся ёмкость |
| Q4 | `priorityScore` ↓ | Включаются, если ёмкость позволяет |

#### Value Density (плотность ценности)

Максимизирует суммарную «отдачу» спринта. Ключевая метрика:

<div class="formula">
valueDensity = priorityScore / effort
</div>

Пример:
- Задача A: приоритет 80, трудозатраты 10ч → VD = 8.0 ← предпочтительнее
- Задача B: приоритет 90, трудозатраты 40ч → VD = 2.25

**Порядок отбора**: единая сортировка по `valueDensity` ↓ → жадный отбор. Квадранты вычисляются, но используются только для статистики отчёта.

#### Hybrid (гибридный)

Совмещает подходы Matrix и Value Density:

| Квадрант | Сортировка | Отличие от Matrix |
|----------|-----------|-------------------|
| Q1 | `valueDensity` ↓ | В Matrix: по `priorityScore` |
| Q2 | `valueDensity` ↓ | В Matrix: по `effort` ↑ |
| Q3 | `priorityScore` ↓ | Совпадает |
| Q4 | `priorityScore` ↓ | Совпадает |

**Идея**: для важных задач (Q1, Q2) оптимизирует эффективность использования ресурсов, а для менее важных (Q3, Q4) — просто берёт наиболее приоритетные.

#### Общий механизм отбора (`selectTasksUniform`)

1. Проход по задачам в порядке, определённом алгоритмом
2. Для каждой задачи проверяются 5 условий:
   - Не исключена вручную
   - Ненулевые трудозатраты
   - Общая ёмкость команды не превышена
   - Ёмкость каждой роли (UI/UX, CA, FE, BE, QA) не превышена
   - Все зависимости уже отобраны
3. Если все условия выполнены → задача включается в спринт
4. Если нет → задача исключается с указанием причины

## 🖥️ Интерфейс и основные элементы

Интерфейс состоит из двух вкладок: **«Планирование спринта»** и **«Критерии оценки»**.

### 📅 Вкладка «Планирование спринта»

1. **Параметры спринта** – поля для ввода продукта, длительности спринта, дат, коэффициента доступности, порога алерта.
2. **Блок «Загрузка команды»** – таблица с ролями, показывающая:
- использованные / доступные часы,
- процент загрузки,
- прогресс-бар,
- поля для ввода FTE% и отпуска (дни).
- Итоговая строка с суммарной загрузкой команды.
3. **Блок «Распределение работ по типам задач»** – таблица, где по ролям показаны часы, распределённые по типам (Bug, Tech, US) и итоговые проценты.
4. **Панель управления списком задач**:
- статистика включённых и исключённых задач,
- поле поиска по названию,
- фильтр по типу задачи,
- кнопки: «Удалить всё», «По приоритету», «Новая задача», «Отбор задач».
5. **Список задач** – каждая задача отображается в виде карточки с:
- порядковым номером,
- индикатором типа,
- названием и ссылкой JIRA,
- комментарием,
- полями для ввода часов по ролям,
- суммарным Effort,
- блоком оценки по критериям (если задача включена),
- кнопками действий (редактировать, исключить/включить, удалить).

### ⚖️ Вкладка «Критерии оценки»

- Список настроенных критериев с названием, аббревиатурой, весом и обоснованием.
- Кнопки для добавления, редактирования, удаления критерия.
- Сброс к значениям по умолчанию.
- Для каждого критерия можно развернуть шкалу оценки (описания для баллов 1–10).
- Вверху отображается общий вес критериев (должен быть 100%).

## 📝 Работа с задачами

### ➕ Создание задачи

1. Нажмите кнопку **«➕ Новая задача»** (или `Ctrl+Alt+N`).
2. Форма откроется с фокусом на поле **«Название»** — можно сразу начинать вводить.
3. Заполните обязательные поля:
- **Название** (уникальное, не менее 5 символов)
- **Ссылка JIRA** (уникальная, должна начинаться с http:// или https://)
- **Тип** (US, Bug, Tech)
  *Пояснение:*
  - **US** (User Story) — новая функциональность, пользовательская история.
  - **Bug** — ошибка, требующая исправления.
  - **Tech** — технический долг, рефакторинг, улучшения архитектуры.
- **Комментарий** (необязательно)
4. Введите оценки по ролям в часах (можно использовать запятую как десятичный разделитель). Суммарный Effort обновляется автоматически.
5. Нажмите **«Создать»**. Задача появится в начале списка и автоматически станет активной (выделится голубой рамкой).

### ✏️ Редактирование задачи

- Нажмите кнопку с карандашом на карточке задачи.
- В модальном окне измените необходимые поля.
- Сохраните изменения.

### 👁️ Исключение / включение задачи

- Нажмите кнопку с изображением глаза (👁) на карточке задачи для исключения.
- Исключённые задачи перемещаются в конец списка и имеют пониженную прозрачность.
- Иконка меняется на 🙈 (закрытый глаз), повторное нажатие возвращает задачу в спринт.

### 🗑️ Удаление задачи

- Нажмите кнопку с корзиной. Задача удаляется **сразу** (без подтверждения).
- В нижней части экрана появляется уведомление (snackbar) с кнопкой **«Отменить»** (5 секунд).
- Нажмите **«Отменить»** для восстановления задачи.

### 🔍 Сортировка и фильтрация

- **Поиск по названию** – фильтрует задачи по вхождению текста.
- **Фильтр по типу** – выпадающий список.
- **Сортировка по приоритету** – кнопка «По приоритету» сортирует задачи по убыванию Priority Score.

### 🖱️ Drag & Drop

Задачи можно перетаскивать, меняя их порядок. Исключённые задачи всегда остаются в конце списка.

## ⚙️ Настройка критериев оценки

1. Перейдите на вкладку **«Критерии оценки»**.
2. Вы увидите список существующих критериев. По умолчанию загружены четыре критерия с весами 40, 30, 20, 10.
3. **Добавить критерий** – кнопка «➕ Добавить». Форма откроется с фокусом на поле «Название». Заполните:
- Название
- Аббревиатуру (1–5 символов, уникальная, без пробелов, первый символ – буква или цифра)
- Вес (от 1 до 100)
- Обоснование веса
- Шкалу оценки (описания для баллов 1–10)
4. **Редактировать** – нажмите на иконку карандаша. Форма откроется с фокусом на поле «Название».
5. **Удалить** – нажмите на иконку корзины.
6. **Сброс к умолчанию** – кнопка «🔄».
7. **Показать/Скрыть шкалу** – кнопка под каждым критерием раскрывает или скрывает описания баллов 1–10.

После изменения критериев Priority Score всех задач пересчитывается автоматически.

## 🤖 Автоматический отбор задач

Функция автоматического отбора позволяет сравнить результаты трёх алгоритмов и применить понравившийся.

### Запуск отбора

1. На вкладке «Планирование спринта» нажмите кнопку **«🤖 Отбор задач»**.
2. Появится модальное окно **«Сравнение алгоритмов автоматического отбора»**.

### Интерфейс сравнения

- **Таблица сравнения** показывает для каждого алгоритма:
- количество отобранных задач,
- загрузку команды (в процентах),
- суммарный Effort,
- суммарный Priority Score,
- среднюю плотность ценности.
Лучшие значения подсвечены зелёным фоном.
- **Кнопка «Рекомендации»** открывает окно с рекомендациями по оптимизации спринта.
- **Детализация по алгоритмам** – раскрывающиеся блоки с квадрантами и исключёнными задачами. При наведении курсора на заголовок блока он подсвечивается, указывая на возможность раскрытия.

### Применение результата

Внизу модального окна расположены кнопки:
- ✅ Применить Matrix
- ✅ Применить Value Density
- ✅ Применить Hybrid

Нажатие на одну из них применяет выбранный алгоритм к текущему списку задач.

## 🎛️ Управление параметрами спринта

Параметры спринта задаются в верхней панели:

- **Продукт** – текстовое поле (произвольное название).
- **Дни спринта** – количество рабочих дней (суббота и воскресенье автоматически пропускаются при расчёте даты окончания).
- **Начало / Окончание** – даты в формате ДД.ММ.ГГГГ.
- **Коэфф.доступности %** – число (по умолчанию 93,5). Влияет на расчёт ёмкости ролей.
- **Порог алерта %** – число (по умолчанию 3,0). Определяет, при каком превышении ёмкости появляется красная подсветка (визуально).

Изменение параметров мгновенно пересчитывает все показатели загрузки.

## 💾 Сохранение и загрузка данных

### 🔄 Автосохранение (localStorage)

Все изменения, которые вы вносите (создание/редактирование задач, изменение параметров спринта, настройка критериев), **автоматически сохраняются в локальном хранилище вашего браузера (`localStorage`)**. Это значит:
- Вы можете без страха обновить страницу или закрыть вкладку — данные не пропадут.
- При следующем открытии приложения вы продолжите работу с того же места.

### 📁 Сохранение в файл

Кнопка **«💾 Сохранить»** (или `Ctrl+Alt+S`) сохраняет текущее состояние (конфигурацию, роли, задачи, критерии) в JSON-файл. Имя файла формируется автоматически: `{Продукт}-sprint-plan-ГГГГ-ММ-ДД.json` (если продукт не задан — `sprint-plan-ГГГГ-ММ-ДД.json`). Это полезно для резервного копирования или передачи данных другому пользователю.

### 📂 Загрузка из файла

Кнопка **«📂 Загрузить»** (или `Ctrl+Alt+O`) открывает диалог выбора JSON-файла. После подтверждения данные загружаются, заменяя текущие. **Важно:** текущие данные будут потеряны, поэтому система запросит подтверждение.

## 🚦 Индикаторы перегрузки

В списке задач для каждой включённой задачи могут появляться **красные метки** вида `+X ч (+Y%)` рядом с полем оценки роли. Они сигнализируют о том, что **суммарная загрузка по этой роли превышает доступную ёмкость** после добавления данной задачи.

- **Как это выглядит:** под полем ввода часов появляется красный ярлык с текстом, например, `+2,5 ч (+15%)`.
- **Что означает:** если вы включите эту задачу, то по данной роли будет перегрузка. Цифры показывают, на сколько часов превышена ёмкость и какой это процент от доступного времени.
- **Зачем это нужно:** помогает сразу видеть, какие роли будут перегружены, и принимать решение о пересмотре состава спринта или корректировке оценок.

Индикаторы перегрузки обновляются в реальном времени при изменении оценок или исключении/включении задач.

## ❓ Часто задаваемые вопросы

**Вопрос:** Почему некоторые задачи не отображаются в списке?  
**Ответ:** Проверьте, не активен ли фильтр по типу или поиск по названию. Сбросьте фильтры, выбрав пустое значение в выпадающем списке и очистив поле поиска.

**Вопрос:** Как изменить порядок задач?  
**Ответ:** Перетащите карточку задачи за иконку с точками (слева). Исключённые задачи автоматически остаются в конце.

**Вопрос:** Можно ли использовать десятичную запятую вместо точки?  
**Ответ:** Да, приложение поддерживает запятую как десятичный разделитель. Настройка сохраняется в `localStorage`.

**Вопрос:** Как сбросить все задачи?  
**Ответ:** Используйте кнопку **«🗑️ Удалить всё»** в панели управления задачами. Подтвердите действие.

**Вопрос:** Почему в блоке «Распределение работ по типам задач» проценты могут быть больше 100%?  
**Ответ:** Это нормально, так как проценты показывают отношение суммарных часов по типу к общей ёмкости команды. Если общая загрузка превышает ёмкость, проценты будут >100%.

**Вопрос:** Поддерживается ли печать?  
**Ответ:** Да, кнопка «🖨️ Печать» открывает стандартное окно печати браузера. При печати отображаются только основные данные задач (номер, тип, название, ссылка, Priority Score, Effort) без кнопок и полей ввода, а таблицы загрузки команды и распределения работ выводятся в компактном виде.

**Вопрос:** Можно ли отменить удаление задачи?  
**Ответ:** Да, после удаления в нижней части экрана появляется уведомление с кнопкой «Отменить». Нажмите её в течение 5 секунд для восстановления.

**Вопрос:** Можно ли установить приложение на телефон?  
**Ответ:** Да, Sprint Planner — это PWA. Откройте приложение в браузере и выберите «Установить» (Chrome) или «На экран Домой» (Safari). После установки оно работает оффлайн.

**Вопрос:** Нужен ли интернет для работы приложения?  
**Ответ:** Нет, приложение полностью клиентское и работает оффлайн. После установки как PWA интернет не нужен вообще. Без сети встроенная справка откроется в упрощённом формате.
