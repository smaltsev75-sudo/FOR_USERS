# PLANNER User Feedback Package

Пакет обратной связи нужен, чтобы реальные пользовательские сигналы не терялись между ИИ-аудитами, релизами и ручной поддержкой.

## Когда использовать

- пользователь сообщает о потере данных, проблеме восстановления или ошибке импорта;
- визуальный дефект зависит от темы, viewport, overflow или печати;
- планирование на большом backlog стало заметно медленнее;
- справка, хоткеи или UI-copy расходятся с фактическим поведением.

## Что просить у пользователя

1. Сценарий: вкладка, тема, размер окна, действие и ожидаемый результат.
2. Фактический результат: что произошло и насколько мешает работе.
3. Диагностику из кнопки `Диагностика`: файл не содержит тексты задач, JIRA-ссылки, комментарии и название продукта.
4. Скриншот или PDF только для визуальных и print-дефектов.

Не просить экспортированный sprint JSON в публичный issue. Если нужен воспроизводимый набор, пользователь должен сделать синтетический план без клиентских данных.

## Шаблон

Сгенерировать актуальный шаблон:

```bash
npm run feedback:template
```

Для конкретного диагностического файла:

```bash
npm run feedback:template -- --diagnostics=sprint-planner-diagnostics-2026-05-24.json
```

## Триаж

- `P1`: пользователь не может открыть приложение, сохранить или восстановить данные.
- `P2`: импорт/экспорт/печать дают неверный результат или вводят в заблуждение.
- `P3`: UI медленный, неудобный или расходится со справкой.
- `P4`: косметика, текст, локальная полировка без риска данных.
