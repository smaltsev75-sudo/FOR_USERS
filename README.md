# Sprint Planner

Инструмент для объективного и прозрачного планирования спринтов в продуктовой разработке.

Sprint Planner помогает Product Owner формировать бэклог спринта на основе формализованных критериев ценности, объективных оценок трудозатрат и жёстких ограничений по ресурсам команды. Работает полностью в браузере, не требует backend, базы данных или внешних сервисов — все данные хранятся локально. Запуск требует локальный HTTP-сервер для подгрузки ES-модулей (см. раздел [Запуск](#запуск-приложения)). Устанавливается как приложение на компьютер и мобильные устройства (PWA).

## Для кого

| Роль | Что даёт приложение |
|------|---------------------|
| **Product Owner** | Воспроизводимый, аргументированный механизм отбора задач. Прозрачная связь состава спринта с OKR. |
| **Scrum Master** | Диагностика перегрузки и недозагрузки ролей. Понимание логики взаимодействия алгоритмов с ёмкостью команды. |
| **Команда** | Прямая зависимость между оценкой трудозатрат и попаданием задачи в спринт. Прозрачные правила. |
| **Стейкхолдеры** | Обоснование состава спринта на основе формализованных критериев и ограничений. |

## Возможности

- **Оценка по критериям** — каждая задача оценивается по нескольким критериям с настраиваемыми весами (OKR, UX, стратегия, риск) → интегральный Priority Score. В v8.29 переработан экран управления критериями: sticky-bar с pill «Сумма весов», авто-баланс к 100%, inline-редактирование веса, drag-and-drop порядка, hover-only edit/delete.
- **Трудозатраты по ролям** — оценка в часах по 5 ролям: UI/UX, CA, FE, BE, QA.
- **Team Capacity Dashboard** (v8.21) — премиум-карточки ролей вместо двух дублирующих блоков (Capacity Strip + role-list). Header с общей загрузкой команды (gauge SVG) + 5 карточек ролей с иконками, прогрессом, FTE/Отпуск-инпутами. Drag задачи подсвечивает сегменты и показывает дельту нагрузки.
- **Density toggle** (v8.14, упрощён до 2 режимов в v8.27.1) — два режима плотности списка задач: Compact / Comfortable. Compact умещает ≈2× больше задач на тот же экран. Выбор переживает F5.
- **View toggle: List / Quadrants** (v8.14, расширен в v8.29.1) — режим группировки задач по 4 приоритетным квадрантам с sticky-headers и собственным summary. С v8.29.1 исключённые из спринта задачи выносятся в отдельную 5-ю секцию «Исключённые из спринта» под Q4 (с приглушённым заголовком). Сворачивание любой секции переживает F5.
- **Task Card Redesign** (v8.22) — компактная карточка задачи с 3 логическими блоками: header (статус/тип/приоритет/title) → estimates (трудозатраты по ролям с иконками) → metrics (критерии + Priority Score). 4× компактнее, sandy palette, без чисто-белого.
- **Hover-only actions** (v8.14) — кнопки edit/delete/exclude скрыты по умолчанию, появляются на hover/focus. Тише визуальный шум.
- **3 алгоритма автоотбора** — Matrix, Value Density, Hybrid (подробнее ниже). В v8.28 переработан экран сравнения: рекомендованный алгоритм подсвечен в шапке, метрики каждого алгоритма показаны компактными карточками с прогресс-барами.
- **Drag & Drop + ↑/↓ controls** — ручное переупорядочивание задач мышью/touchpad или явными кнопками для keyboard/touch fallback.
- **Исключение/включение** — ручное управление составом спринта.
- **Отмена удаления** — при удалении задачи появляется кнопка «Отменить» (5 секунд).
- **Импорт/экспорт** — сохранение и загрузка данных в JSON. При загрузке приложение заранее показывает компактную диагностику невалидных полей; подробный список раскрывается в подтверждении импорта.
- **Диагностический пакет** — кнопка «Диагностика» (`Ctrl+Alt+D`) скачивает JSON для разбора проблем: версия, browser/storage/service worker/cache и агрегаты состояния без текстов задач, JIRA URL, комментариев и названия продукта; после скачивания появляется короткое уведомление.
- **Центр восстановления** — кнопка «Резерв» показывает локальный pre-migration backup, сравнивает его с текущим состоянием по количествам задач/критериев и позволяет скачать или восстановить backup через тот же миграционный путь, что и импорт JSON.
- **Автосохранение** — все изменения сохраняются в localStorage.
- **Горячие клавиши** — Ctrl+Alt+N (новая задача), Ctrl+Alt+S (сохранить), Ctrl+Alt+O (загрузить), Ctrl+Alt+F (поиск), Ctrl+Alt+P (печать), Ctrl+Alt+D (диагностика), Delete (удалить задачу), Esc (закрыть окно). Полный список с macOS-эквивалентами — в [`docs/UserManual.md`](docs/UserManual.md).
- **Светлая (песочная) и тёмная тема** — светлая тема выполнена в тёплых песочных тонах (без чисто-белого), все пары контраста соответствуют WCAG 2.1 AA ≥ 4.5:1.
- **PWA** — установка на рабочий стол, полная оффлайн-работа (включая встроенную справку: marked и DOMPurify лежат локально в `js/vendor/`, без CDN).

## Алгоритмы отбора задач

Приложение предлагает три алгоритма автоматического отбора задач в спринт. Все три используют жадный алгоритм (greedy knapsack) с проверкой ёмкости по каждой роли.

### Priority-Effort Matrix

Задачи распределяются по 4 квадрантам относительно медиан приоритета и трудозатрат:

| Квадрант | Описание | Стратегия |
|----------|----------|-----------|
| Q1 | Высокий приоритет, низкие трудозатраты | «Лёгкие победы» — берём первыми |
| Q2 | Высокий приоритет, высокие трудозатраты | Стратегические задачи — берём менее тяжёлые |
| Q3 | Низкий приоритет, низкие трудозатраты | Заполнители — дополняем оставшуюся ёмкость |
| Q4 | Низкий приоритет, высокие трудозатраты | Откладываем |

### Value Density

Максимизирует «отдачу» спринта. Сортирует задачи по плотности ценности (Priority Score / Effort) и отбирает жадно. Предпочитает задачи с наибольшей отдачей на час работы.

### Hybrid

Совмещает подходы: для важных задач (Q1, Q2) оптимизирует эффективность (как Value Density), для менее важных (Q3, Q4) — берёт наиболее приоритетные (как Matrix).

## Требования

Для запуска нужен **один из**:
- Python 3
- Node.js
- PHP

Интернет не требуется.

## Установка и запуск

> ⚠️ **Не открывайте `index.html` двойным кликом.** Приложение использует ES-модули и требует HTTP-сервера.

### Рекомендуемый способ — скрипт из папки проекта

| ОС | Команда |
|----|---------|
| Windows | Запустите `start-server.bat` — откроет браузер автоматически |
| Linux / macOS | `bash start-server.sh` — автоопределяет Python 3 / Node.js / PHP |

### Альтернативные способы

```bash
# Python
python -m http.server 8123        # Windows
python3 -m http.server 8123       # Linux / macOS

# Node.js
npx http-server -p 8123

# PHP (Linux / macOS)
php -S localhost:8123
```

После запуска откройте: **http://localhost:8123**

> Используется нестандартный порт 8123, чтобы не конфликтовать с
> Service Worker'ами других локальных проектов, которые часто живут на
> 8000/8080. Если в браузере открывается **не** Sprint Planner — откройте
> `http://localhost:8123/dev-tools/_clear-sw.html` и подождите 2 секунды.

### Доступ с мобильных устройств

Запустите сервер на компьютере и откройте в браузере телефона/планшета:
`http://<ip-компьютера>:8123` (оба устройства в одной Wi-Fi сети).

### Установка как приложение (PWA)

После первого открытия можно установить на рабочий стол или мобильное устройство:

| Платформа | Как установить |
|-----------|----------------|
| Chrome / Edge | Иконка установки (⊕) в адресной строке → «Установить» |
| iOS (Safari) | «Поделиться» → «На экран "Домой"» |
| Android (Chrome) | Меню (⋮) → «Установить приложение» |

После установки приложение работает без интернета и без запущенного сервера.

## Решение типовых проблем

### Запуск

| Проблема | Решение |
|----------|---------|
| `Failed to load module script` | Файл открыт через `file://` — запустите через HTTP-сервер |
| Порт 8123 занят чужим процессом | `netstat -ano \| findstr :8123` (Windows) / `lsof -i :8123` (Unix) → `taskkill /F /PID <pid>` или `kill <pid>`. Если порт занят другим Sprint Planner — это OK, e2e-runner (v8.30.33+) сам определит свой сервер по `<title>` signature. Старый legacy совет «8080» больше не применим: порт зафиксирован на 8123 в playwright.config.js и start-server.*. |
| `Permission denied` (Linux) | Используйте `bash start-server.sh` |
| Не найден Python / Node.js / PHP | Установите [Python 3](https://python.org) или [Node.js](https://nodejs.org) |

### Работа в браузере

| Проблема | Решение |
|----------|---------|
| Пустая страница | DevTools (F12) → Console → найдите ошибку; используйте Chrome/Firefox/Safari |
| Данные пропали после перезагрузки | Проверьте, не включён ли приватный режим (localStorage заблокирован) |
| Приложение не обновляется | DevTools → Application → Service Workers → Unregister → обновите страницу |
| Не открывается справка | Проверьте наличие файла `docs/UserManual.md` в проекте |

## Структура проекта

```
PLANNER/
├── index.html              ← entry point приложения
├── manifest.json           ← PWA manifest
├── sw.js                   ← Service Worker (PWA cache)
├── start-server.bat / .sh  ← скрипты запуска HTTP-сервера
├── README.md               ← этот файл
├── HANDOFF.md              ← памятка для передачи коллеге
├── CLAUDE.md               ← инструкции для AI-ассистента (Claude Code)
├── TestData.json           ← тестовый набор данных (загружается через UI)
│
├── js/                     ← модули JS (ES6 modules)
│   ├── app.js              ← инициализация приложения
│   ├── controllers/        ← оркестрация event ↔ store
│   ├── domain/             ← чистая бизнес-логика (без DOM/Store)
│   ├── services/           ← сервисы (storage, message, format)
│   ├── state/              ← Store + persistence facade/submodules
│   ├── ui/                 ← рендеринг компонентов
│   └── utils/              ← вспомогательные модули
│
├── css/                    ← стилевые модули
├── icons/                  ← иконки приложения (PNG для PWA-инсталла + SVG fallback)
│
├── docs/                   ← техническая и пользовательская документация
│   ├── UserManual.md       ← справка пользователя (открывается через ❓)
│   ├── ARCHITECTURE.md     ← архитектурная документация для разработчиков
│   ├── MODULE_MAP.md       ← autogenerated карта JS-модулей (`npm run docs:modules`)
│   ├── LESSONS_LOG.md      ← архив накопленных инженерных уроков
│   └── RELEASE_NOTES.md    ← история изменений
│
├── dev-tools/              ← утилиты для разработки
│   └── _clear-sw.html      ← страница для сброса Service Worker и кэшей
│
└── tests/                  ← unit (Jest) + e2e (Playwright) тесты
```
